## Users

- **Основной пользователь — менеджер лизинговой компании ТАЛК.** Работает в портале каждый день: заводит сделки, проверяет клиента, ведёт сделку по стадиям, записывает результаты звонков, ставит и закрывает задачи, загружает документы. Работает с настольного компьютера и иногда с телефона.
- **Второй — руководитель.** Смотрит главную страницу: сколько сделок в работе, что заключено, что застряло и что просрочено. Переходит к спискам за этими цифрами.
- **Зрители демонстрации** — кураторы проекта «Гибридные лидеры» и команда заказчика Sber2B. Смотрят, но не работают; роль только для просмотра.
- Подтверждено владельцем 27.10.2026.

## Product Purpose

Единый контур лизинговой сделки от заявки до работы с просрочкой.

Стенд одновременно:
- показ кураторам;
- референс и основа ТЗ для Sber2B (`docs/ТЗ.md`, `docs/openapi.yaml`);
- рабочий стенд, на котором реальные сотрудники ТАЛК пробуют пройти свои сценарии.

Это прототип, а не продукт.

**Успех:** менеджер проходит частые сценарии без поиска действий и без вспоминания данных с другого экрана; руководитель получает ответы на свои вопросы с главной.

## Positioning

Один контур вместо разрозненных инструментов:
- сделка по семи стадиям (заявка → оценка клиента → решение → договор → мониторинг → просрочка до 30 дней → просрочка свыше 30 дней);
- класс кредитоспособности по методике ТАЛК, рассчитанный из PDF бухгалтерской отчётности;
- раннее предупреждение о просрочке по балльной карте.

Всё это связано со сделкой и клиентом. Подтверждено владельцем 27.10.2026.

## Operating Context

- **Частые сценарии менеджера:**
  1. создать сделку с клиентом и контактом;
  2. найти сделку по клиенту;
  3. записать результат звонка и следующий шаг;
  4. перевести сделку на следующую стадию и поправить сумму;
  5. отметить выполнение просроченных и сегодняшних задач;
  6. оформить отказ с причиной;
  7. рассчитать класс по PDF отчётности и сохранить его в сделку.
- **Документы клиента** — PDF бухгалтерской отчётности (формы 0710001 и 0710002), договоры, сканы.
- **Внешние источники:** DaData (организация по ИНН), ГИР БО (годовая отчётность ФНС), Банк России (ключевая ставка). Контур, СПАРК, 1С и CRM подключены только интерфейсом, ответы условные. Любой источник может быть недоступен: тогда показывается сохранённый ответ или условный пример с пометкой.
- **Решения о клиентах в красной зоне** принимает коллегиальный орган (КПА). Клиентов в просрочке 30+ ведёт подразделение по проблемным активам (СПА). Расшифровки этих сокращений в проекте нет.

## Capabilities and Constraints

- **Роли:** admin, curator, sber2b, talk, team. Вести сделки могут admin, team, talk; curator и sber2b только смотрят.
- **Рабочие модули:** сделки (канбан и список), клиенты, задачи, лента комментариев, документы, проверка клиента по ИНН, расчёт класса, мониторинг. Стадии «Решение», «Договор», «Просрочка» помечены «в разработке».
- **Исход сделки:** успех — переход на стадию «Договор». Закрытие — только «Отказ» с причиной. Термин «выигранная сделка» не используется (решение владельца). Сделку можно вернуть из отказа и из архива.
- **Все клиентские пути сохраняются,** включая возврат из просрочки в мониторинг (решение владельца).
- **Технические рамки:**
  - Node.js без фреймворков и без шага сборки, HTML собирается на сервере, один CSS-файл с токенами;
  - клиентского JS — минимум;
  - весь стек на сервере не больше 600 МБ памяти;
  - без тяжёлых библиотек и внешних скриптов.
- **Нельзя менять** формулы расчёта класса (`seed/calc/core.js`) и рабочие данные (`data/`).
- **Термины:** «сделка», «Создать сделку», «Проверить клиента по ИНН», «Рассчитать класс», «Оформить отказ», «Без клиента · …» для сделки без клиента.

## Brand Commitments

- Название «Контур контроля лизинговой сделки» — рабочее. Фирменного стиля нет: ни ТАЛК, ни Сбера (подтверждено владельцем 27.10.2026).

## Product Principles

1. **Ежедневная работа менеджера важнее показа.** Частый сценарий должен быть коротким даже ценой менее эффектной демонстрации.
2. **Сделка — центр.** Клиент, задачи, документы, класс и мониторинг видны из сделки и ведут обратно к ней.
3. **Честность данных.** Условное и недоступное всегда помечено; пример не выдаётся за результат.
4. **Действие с последствиями — явно.** Просрочка, отказ, архив и передача сделки — с подтверждением и записью в ленту; обычный шаг вперёд — без лишних вопросов.
