# ГИР БО — государственный информационный ресурс бухгалтерской (финансовой) отчётности

Проверено 2026-10-22 с сервера прототипа (запросы из контейнера `app`). Коннектор: `app/connectors/fin.js`, метод `fin/reports`.

## Что это и на каком основании

- Оператор — ФНС России (ст. 18 Федерального закона от 06.12.2011 № 402-ФЗ, с отчётности за 2019 год). Сайт — bo.nalog.gov.ru (bo.nalog.ru отдаёт HTML-интерфейс).
- Организации из перечня постановления Правительства от 16.09.2022 № 1624 (стратегические, ОПК, под санкциями и др.) вправе ограничить доступ к своей отчётности. Для таких ИНН ресурс отчётность не отдаёт — коннектор возвращает `found: false`, страница пишет «не найдена или не раскрыта». В проверке так вели себя две крупные публичные компании из трёх.
- **Официального API нет.** Используется JSON, которым пользуется сам сайт. Отдельных условий использования для автоматического доступа на сайте не найдено; форма ответов может измениться без предупреждения. Поэтому: ответы кэшируются на 7 дней (при сбое — последний сохранённый ответ), запросов — два на организацию, запасной источник — parser-api.com.
- Ключ не нужен. С сервера прототипа отвечает за 0,1–0,4 с.
- Отчётность только **годовая**: баланс на 31.12 с графами на 31.12 двух предыдущих лет, ОПиУ за год и предыдущий год. Квартальной отчётности в ресурсе нет — для заключения калькулятора (4 квартальные даты) её запрашивают у клиента.

## Запросы

1. Поиск по ИНН: `GET https://bo.nalog.gov.ru/advanced-search/organizations/search?query=<ИНН>&page=0`

   ```json
   {"content": [{"id": 1234567, "inn": "<strong><ИНН></strong>", "shortName": "ПАО \"…\"", "ogrn": "…",
     "index": "…", "region": "…", "city": "…", "street": "…", "house": "…", "okved2": "…", "okopf": 12247,
     "statusCode": "ACTIVE", "statusDate": "…", "hasKfo": …}], "…": "…"}
   ```

   ИНН в ответе обёрнут в `<strong>` (подсветка совпадения) — коннектор снимает теги и сравнивает точно.

2. Список отчётности со значениями: `GET https://bo.nalog.gov.ru/nbo/organizations/<id>/bfo/` — массив по годам (в проверке — 5 лет):

   ```json
   [{"id": 28400000, "period": "2025", "knd": "0710099", "actualBfoDate": "2026-03-27", "gainSum": …, "actives": …,
     "organizationInfo": {"fullName": "…", "inn": "…", "kpp": "…", "okpo": "…", "okopf": {…}, "okfs": {…}},
     "typeCorrections": [{"type": 12, "correction": {
        "balance": {"okud": "0710001", "current1600": …, "previous1600": …, "beforePrevious1600": …, "expl1600": null, …},
        "financialResult": {"okud": "0710002", "current2110": …, "previous2110": …, …},
        "capitalChange": {…}, "fundsMovement": {…}}}]}]
   ```

   Отдельный запрос `GET /nbo/bfo/<id>/details` отдаёт то же содержимое одного года — коннектору он не нужен.

## Маппинг на коды строк калькулятора

| Калькулятор | ГИР БО |
|---|---|
| баланс, графа на 31.12.Y (основная) | `balance.current<код>` |
| баланс, 31.12.Y−1 и 31.12.Y−2 (сравнительные) | `balance.previous<код>`, `balance.beforePrevious<код>` |
| ОПиУ за Y (12 мес., основная) / за Y−1 | `financialResult.current<код>` / `financialResult.previous<код>` |

Коды: 1200, 1230, 1240, 1250, 1300, 1370, 1500, 1530, 1540, 1550, 1600, 1700, 2110, 2200, 2400. Значения в тыс. руб.
Пустая строка формы приходит как `null` (в документе — прочерк): для расчёта это 0; отсутствием данных считается только
пропуск итоговых строк (1200, 1300, 1500, 1600, 1700, 2110). `knd` 0710099 — полная форма, 0710096 — упрощённая
(строки укрупнены, расчёт справочный).
