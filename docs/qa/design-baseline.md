# Базовые замеры до дизайн-правок

Этап 2 ревью со скиллом Impeccable. Только числа, без выводов о причинах.
Дата 27.10.2026. Ветка `design/impeccable-review`; код интерфейса совпадает с `8e9839b` (метка `pre-design-review`).

## Условия

- **Экземпляр.** Локальный, `http://localhost:3088`, база с нуля в `tmp/design-base`. Папка исключена из git; путь короткий, потому что SQLite ломается на длинных путях Windows.
- **Данные.** При первом запуске база сама наполняется 14 условными сделками.
- **Вход.** Менеджер (роль `team`) из `scripts/create-users.js`; набор действий на экранах зависит от роли.
- **Внешние источники.** DaData и ГИР БО не настроены (нет токена), поэтому в карточке сделки виден блок «Клиент» с пометкой о недоступности источника.
- **Браузер.** Встроенный браузер Claude (Chromium), размер окна эмулировался.
- **Что считается.** Счётчик — скрипт в странице, правила одинаковы для всех экранов:
  - **блоки верхнего уровня** — видимые непустые прямые дети `main.page`; сетка `.dash` раскладывается на свои панели;
  - **действия** — видимые `a[href]`, `button`, `summary` внутри `main`, без левого меню. Содержимое закрытого `details` не считается, его заголовок — считается;
  - **основные** — действия с зелёной заливкой `rgb(27, 100, 70)` (`--accent`);
  - **поля** — видимые `input`, `select`, `textarea`;
  - **высота** — `document.documentElement.scrollHeight`.

## б) Семь сценариев (раздел 7 `docs/design-context.md`)

**Как считалось.** Минимальный путь от главной после входа, **посчитан по интерфейсу, без хронометража**. Правила те же, что в `ux-report.md`:
- клик — нажатие на поле, кнопку, ссылку или пункт списка; набор текста не считается;
- экран — загрузка страницы, в том числе перезагрузка после отправки формы;
- прокрутка указана отдельно.

Сценарий 7 через интерфейс не проходился: на локальном экземпляре нет ключа распознавания. Он **посчитан по коду**.

## в) Сканер Impeccable (`impeccable detect`, движок 0.1.18)

**Чем запускался.** Движком скилла (`.claude/skills/impeccable/scripts/impeccable detect`) — это тот же детектор, что `npx impeccable detect`, только в закреплённой версии. Кэш движка — `tmp/impeccable-home`, телеметрия выключена (`IMPECCABLE_NO_TELEMETRY=1`).

**1. Статические файлы `app/public`.** 6 файлов (`.css`, `.js`) проверены только по шаблонам. Правила, которым нужна отрисовка страницы (мелкий текст, контраст и др.), не запускались.

| Категория | Правило | Важность | Число | Где |
|---|---|---|---|---|
| slop | side-tab | warning | 1 | `style.css:82`, `.stage.working` — цветная полоса 3 px сверху карточки стадии на «Схеме процесса» |

**2. Запущенный экземпляр по адресу** (`/login`, `/`, `/deals`, `/deals/4`, `/deals/list`). Сканер не передаёт cookie сессии, поэтому **все страницы за входом он не смог прочитать**: каждый адрес перенаправил его на `/login`. Результат по всем пяти адресам одинаковый — это страница входа:

| Категория | Правило | Важность | Число |
|---|---|---|---|
| quality | unbalanced-heading | advisory | 1 (заголовок «Контур контроля лизинговой сделки» на странице входа) |

**3. Страницы за входом — через сохранённые снимки.** HTML взят с сессией менеджера. В него добавлен `<base href="http://localhost:3088/">`, чтобы подтянулись стили, затем снимок отрисован сканером как `file://`.
- Это **копия на момент снятия**, не живая страница.
- Скрипты страницы выполнялись относительно сервера.
- Снимки лежат в `tmp/design-snap/` (вне git).

## Что не замерено

- Время выполнения сценариев — хронометража не было.
- Сценарий 7 через интерфейс — нет ключа распознавания; посчитан по коду.
- Контраст в отрисованной странице для всех элементов — посчитаны только пары токенов. Сканер проверил контраст на четырёх снимках и нашёл только подсказку в поле поиска.
- Экраны за входом сканер видел только как сохранённые снимки, не как живые страницы.
- Роль руководителя (только просмотр) — замеры сделаны для менеджера.
- Тёмная тема в браузере — проверены только расчётные пары.
