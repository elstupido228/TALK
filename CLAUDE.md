# Бриф для Claude Code: портал-прототип «Контур контроля лизинговой сделки» (рабочее название)

## 1. Цель
Прототип на сервере (домен talk.perveev.com): единый портал со страницами, учётными записями, двумя калькуляторами внутри, подключением нейросети и слоем коннекторов. Назначение: показ кураторам проекта «Гибридные лидеры» (22–23.10.2026) и референс + основа ТЗ для команды Sber2B. Это демонстрация, не продукт. Главная ценность для Sber2B: docs/ТЗ.md и docs/openapi.yaml.

## 2. Что нельзя
- Не трогать каталоги ~/openclaw и ~/openclaw-team и их контейнеры (боты должны остаться живыми).
- Не класть в репозиторий ключи, .env, реальные документы клиентов, базы. .gitignore создать до первого коммита.
- Не отправлять в OpenAI реальные PDF клиентов. Тестировать только на условных документах.
- Формулы расчёта класса не менять (core.js). Любое изменение — только по отдельному решению пользователя.
- Не объявлять результат достигнутым без замера. Каждый пункт приёмки подтверждать выводом команды.

## 3. Сервер
Ubuntu 24.04, 4 ГБ RAM (свободно около 2,3 ГБ, своп уже занят), 33 ГБ диска. Docker 29, Compose v5, git. Порты 80/443 свободны и доступны снаружи. DNS: talk.perveev.com -> 37.46.19.89 (Cloudflare, DNS only). Рабочий каталог ~/talk-proto (chmod 700), секреты в ~/talk-proto/.env (OPENAI_API_KEY, DADATA_TOKEN, PARSERAPI_KEY). Деплой вручную: `git pull && docker compose up -d --build`; GitHub Actions по SSH — позже.

## 4. Архитектура
Отдельный Compose-проект: Caddy (80/443, автосертификат) + один сервис Node.js + SQLite (том). Ядро расчётов — JS (core.js, features.js) без переписывания. Потолок памяти: весь стек до 600 МБ; проверять `free -h` под нагрузкой.

## 5. Страницы
1. Вход (логин/пароль, хэши, cookie-сессии, ограничение попыток, роли: admin, curator, sber2b, talk, team).
2. «Жизненный цикл сделки»: лента стадий — заявка, оценка клиента, решение, договор, мониторинг, просрочка до 30 дней, просрочка свыше 30 дней. Рабочие: «Оценка клиента» = калькулятор класса, «Мониторинг» = раннее предупреждение. Остальные — целевая схема/бэклог, помечены явно.
3. «Источники данных»: список коннекторов со статусом (живой / песочница), журнал запросов.
4. «О проекте».

## 6. Калькулятор класса (seed/calc)
- Правила: класс 1 при К5 ≥ 0,10 и S ≤ 1,25; класс 2 при S ≤ 2,35 и К5 ≥ 0; иначе 3; отказ при классе 3 на всех четырёх датах.
- Тесты: 124 случая (04_тестовые_случаи_вход.csv, 05_эталон_результаты_Excel.csv, gen.js, parity.json). Требуется 124/124 на сервере.
- page.src.html: плейсхолдеры /*__CORE__*/ /*__DEMO__*/ /*__TPL__*/ /*__META__*/ /*__REF__*/ — написать новую сборку (build.py исходного проекта не передан). Вызов `sample` (строки ~548–602) работал только внутри claude.ai: заменить на POST /api/extract на сервере.
- demo_synthetic.json: три вымышленных пакета отчётности (классы 1, 2, 3; проверено core.js). Это демо-данные; значения придуманы, баланс сходится.

## 7. Шлюз распознавания PDF (OpenAI)
- POST /api/extract: PDF -> рендер страниц в изображения -> vision-модель -> JSON по кодам строк (1200, 1230, 1240, 1250, 1300, 1370, 1500, 1530, 1540, 1550, 1600, 1700, 2110, 2200, 2400) на пять дат. Схема ответа взять из кода page.src.html.
- Модель — переменная OPENAI_MODEL. Замерить кандидатов: gpt-5.4-mini, gpt-5.5, gpt-5.6-luna (pro-версии не использовать). Доступность проверить запросом /v1/models.
- Эталон: прежний результат 59 из 60 ячеек к ручному вводу. Порог приёмки: не ниже 57 из 60; ниже — сообщить пользователю, не подгонять. Набор для замера — условные PDF, сгенерированные из demo_synthetic.json (создать генератор).
- Ключ OpenAI общий с группой ботов: поставить лимит запросов на сервере (например, 50 в сутки) и логировать расход.

## 8. Раннее предупреждение (seed/ews)
- Порядок: gen_data.py -> build_features.js -> train.py 2024-03-31 -> check_parity.js -> build_page.py. Данные синтетические (420 клиентов, 607 договоров). Метрика Gini 0,69 получена на условных данных и в материалах подаётся только с этой оговоркой.
- demo.json и snapshots.json не переданы: пересоздаются gen_data.py.
- Встроить как страницу «Мониторинг»: выбор клиента, балльная карта, динамика факторов. Добавить на странице ключевую ставку Банка России (коннектор ЦБ).

## 9. Коннекторы (слой /api/connectors/*)
Единый интерфейс, кэш ответов в SQLite, журнал, режим «живой/песочница».
- DaData «Организация по ИНН»: токен в Authorization: Token ...; бесплатно 10 000 запросов в сутки; поля — названия, статус (действует/ликвидируется/банкрот), адрес, ОКВЭД, руководитель.
- Банк России DailyInfoWebServ: ключевая ставка (KeyRate), курсы (GetCursOnDate).
- Бухгалтерская отчётность: проверить parser-api.com (200 запросов в месяц бесплатно, условия не проверены) и доступность ГИР БО. Перед использованием записать в docs/ ответ API и условия использования. Сделать маппинг на коды строк. Не сработает — оставить песочницу и сообщить пользователю.
- Контур, СПАРК, 1С, CRM: только интерфейс и песочница-заглушки.
- Демо-сценарий: ИНН публичной компании вне портфеля ТАЛК и СберЛизинга -> DaData -> отчётность -> калькулятор -> класс. Заранее сохранить 2–3 такие компании в кэш (запасной вариант без интернета).
- MCP-сервер — тонкая обёртка над API, после защиты, не в первой версии.
